# Router flow queue and WRED audit

Compatibility profile: ISR4331 using IOS XE 17.x public QoS guides. Catalyst L2/L3/PoE nodes retain the selected C9300 IOS XE 17.12 profile and reject these router flow-queue/WRED commands. Exact ISR4331 release-specific hardware drop curves and scheduling quanta have not been observed on a native 17.12 device.

## References and interpretation

- [ISR4000 family datasheet](https://www.cisco.com/c/en/us/products/collateral/routers/4000-series-integrated-services-routers-isr/data_sheet-c78-732542.pdf) establishes the platform's CBWFQ/WRED capability.
- [IOS XE 17 scheduling](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/qos/b-quality-of-service/m_qos-scheduling.html) describes class scheduling and 16 hashed flow queues.
- [IOS XE 17 queue limits and WRED](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/qos/b-quality-of-service/m_qos-queue_management_and_congestion_avoidance.html) describes per-flow limits, queue-depth averaging and differentiated curves. Its hardware examples are QFP/ASR examples; they are not independent measurements of the selected ISR4331.
- [IOS XE 17 DiffServ WRED](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/qos/b-quality-of-service/m_qos-conavd-diffserv-wred.html) and [QoS command reference](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/qos/command/qos-cr-book/qos-q1.html) pin mode, threshold, probability and reset syntax.
- [IOS XE 17 WRED ECN](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/qos/b-quality-of-service/m_qos-conavd-wred-ecn-0.html) distinguishes ECT/CE treatment in the random zone and dropping above the maximum.

The simulator uses an original byte-fair finish-tag scheduler and a linear interpolation of early-drop probability between explicit minimum and maximum thresholds. This is a bounded teaching approximation. It does not reproduce Cisco's exact random-curve calibration, memory blocks, adaptive resource thresholds or TCP endpoint congestion-control algorithms.

## Bounds and import compatibility

- Flow queue count is fixed at 16. The original stable five-tuple hash is not a Cisco hardware hash. Queue-limit applies independently to each flow bucket; aggregate pending frames remain capped at 16,384 per physical output port. The default flow-bucket limit is 16 packets; ordinary class queues retain the simulator's 64-packet default. Explicit limits remain 1–4096 packets; WRED requires at least two slots so its maximum threshold can remain below the limit.
- Explicit WRED thresholds control real behavior. Implicit curve defaults are proportional teaching defaults: maximum near half the effective limit; precedence raises minimum thresholds; AF drop precedence lowers them. These defaults, the linear probability curve, idle-decay packet-time estimate and fair-scheduler finish tags are not device-certified. Configure explicit curves for repeatable labs requiring particular thresholds.
- With fair-queue, each actual bucket maintains its own depth average; aggregate displayed mean depth sums them. This is the bounded adapter for the 16 flow queues, not a complete hardware queue database.
- Hierarchical policies, byte/time units, discard-class/CoS/MPLS curves, configurable dynamic queue counts, priority WRED, input/CoPP/logical-interface queues, hardware resource starvation and TCP congestion response remain unsupported and reject where exposed. No artificial endpoint throughput success is inferred from CE marks.
- Mode changes clear old-mode curve overrides. The exact native retention behavior across a mode change is unverified. Valid no-curve arguments are parsed before resetting; behavior for supplied values that differ from current configuration is not device-certified.
- Old `fairQueue:true` and `randomDetect:true` imports now acquire real router behavior. Explicit false flags remain inert. Malformed/unsupported active settings fail closed with diagnostics. Rendered unsupported settings keep a rejecting token rather than silently becoming supported defaults; an unsuccessful CLI replay is not a migration guarantee. Remove/replace incompatible settings first.
- Changing an attached policy flushes its pending frames with reset drops and cancels old scheduler work. Runtime counters are local operational state, rebuilt after reload; saved configuration persists. Marking, policing, original pre-mark class selection and physical/SVI precedence remain in their existing processing stages.
