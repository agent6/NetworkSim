# Repairs found by the current parser audit

The current-only six-profile registry/argument audit found concrete behavior defects while expanding independent context fixtures. Source registry presence and parser acceptance remain separate from packet/native fidelity. Historical paired sandbox observations are preserved at their original source hashes rather than rewritten after repairs.

| Defect | Repair | Executable evidence |
| --- | --- | --- |
| `show ip igmp snooping` and its groups/mrouter/querier variants fell through to the shorter generic IGMP formatter and rejected | Select the dedicated snooping formatter; recognize the advertised VLAN filter; render actual learned multicast groups/router/querier entries and configured static router ports | PARSER-01 transmits real IGMP reports/queries, verifies learned entries and native-shaped table headings, VLAN filtering, invalid inputs and read-only state |
| `encapsulation dot1q` was advertised on ordinary physical ports even though the handler requires a subinterface and WLC/AP profiles cannot create one | Advertise only in an actual modeled Ethernet subinterface context; keep router/switch subinterface behavior | PARSER-02 checks all six profiles, public context help, rejected WLC/AP creation and actual subinterface configuration |
| IPv6 EIGRP `summary-metric` incorrectly rejected as “not implemented in the reference” | Family-checked IPv4/IPv6 prefix, vector, optional/distance-only override, local Null0 distance, AD255 advertisement suppression, contextual help/removal, replayable named topology rendering | SUM6-01/02 use lost/delivered classic/named IPv6 UPDATE vectors, actual echo, metric/AD fallback, suppression, no/default and saved/project reload; SUM6-03 validates family/bounds/atomicity/help and IPv4 mask compatibility |
| Legal Windows WLAN profile names such as `constructor` could be accepted but made the lab unloadable | Allow literal names only at the narrow audited profile dictionary entry position; nested unsafe properties still reject | WIN-29 exercises constructor/toString/__proto__ as own records through save/load/connect and confirms child unsafe-key rejection |

The IGMP table omits untracked native fields. Version cells remain blank because the logical received IGMP model does not record an actual wire version; no v2/v3 value is invented. Not every native snooping detail/count/filter option is implemented. The dot1q restriction documents the simulator's modeled contexts, not a claim that Cisco universally forbids subinterfaces on every WLC/AP product.

IPv6 summary-metric support is confirmed in Cisco's [XE 17 EIGRP guide](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/ip-routing/b-ip-routing/m_ire-enhanced-igrp.html), [summary-metric command reference](https://www.cisco.com/c/en/us/td/docs/ios-xml/ios/iproute_eigrp/command/ire-cr-book/ire-s1.html), and the Cisco-published [XE 17.12.1 EIGRP YANG model](https://raw.githubusercontent.com/YangModels/yang/main/vendor/cisco/xe/17121/Cisco-IOS-XE-eigrp.yang). The model explicitly uses the shared metric/distance fields in classic and named IPv6 groupings. The scalar/vector math uses the existing logical EIGRP packet model; native binary TLVs, every process/topology option and device-image equivalence are not claimed. MTU is retained as a configured summary metric component; the existing logical vector does not encode all native attributes.

The [C9300 XE 17.12 multicast reference](https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst9300/software/release/17-12/command_reference/b_1712_9300_cr/ip_multicast_routing.html) supplies the snooping grammar and table field layout. Tests in `tests/parser-audit-regressions.test.ts`, `tests/eigrp-summary-metric.test.ts` and `tests/windows-cli.test.ts` are original implementation regressions, not copied Cisco/sandbox code or captured native transcripts.
