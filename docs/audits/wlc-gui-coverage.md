# WLC, AP, laptop, and PoE GUI coverage

Audit date: 2026-10-16. Reference profile: Catalyst 9800 IOS XE Dublin 17.12.x; Catalyst 9115 lightweight inspired AP; generic 24-port PoE+ switch. These are teaching profiles, not Cisco firmware.

The reproducible [field inventory](wireless-gui-inventory.json) is generated by `node scripts/audit-wireless-gui.mjs`. It extracts every named field template from the wireless and PoE forms, including repeated port fields and the AP assignment key, and separately inventories the AP's read-only controller displays. Each entry identifies the input, default, validation, parser, persistent state, operational/packet dependency, and relevant test evidence. Source hashes make stale extraction visible.

All 74 configuration field templates have source-to-runtime traces, including read-only existing IDs/built-in names and the hidden AP assignment key. Twelve are reference dropdowns. The additional hidden `policy-tag-definitions` form marker controls compatibility with older form submissions; it is inventoried separately because it is not persistent device configuration. Fields remain classified **partial** under the task's strict eight-level definition: every input does not yet have a complete boundary, default, negation, reload, browser, and Cisco hardware comparison matrix. These counts describe the existing implementation, not the entire Cisco Web GUI.

## Existing page and operational coverage

| WLC page | Inputs and resulting behavior | Evidence and remaining scope |
| --- | --- | --- |
| Overview | Hostname, management interface/IP/mask/gateway/DNS; real AP/client summary | Form uses shared IOS parser. DNS replacement corrected. Physical data egress is the single modeled GigabitEthernet1. Arbitrary management SVI/chassis behavior is incomplete. |
| WLANs | Name/ID/SSID/security/PSK/dot1x list/status/broadcast | Delivered CAPWAP configuration changes advertisement, authentication and existing sessions. Existing IDs are read-only; differing CLI IDs reject instead of being ignored. Exact hardware errors/default constraints remain unverified. |
| Policy profiles | VLAN, central/local switching, enabled, session timeout | Actual VLAN Ethernet/CAPWAP paths; session timeout causes reauthentication. Dedicated wireless policy ACL/QoS fields are absent. |
| Tags & profiles | WLAN/policy mappings; AP join, Flex, site, RF profiles and tags | Site profile/tag changes rejoin. Wrong-band RF mappings reject. Missing dependencies deactivate service. Invalid references and duplicate form rows reject transactionally. |
| Access points | AP Ethernet MAC and policy/site/RF assignments | Delivered AP configuration and rejoin. Removing an assignment resets the visible AP's override. Off-topology assignments are preserved. AP authorization/certificates/image management are absent. |

The controller form validates an isolated draft through `IOSSession` before committing. It preserves properties not represented by the form, including disabled AKM/WPA2 flags, AP join descriptions and Flex VLAN dictionaries. RF channels now have their own represented control. Clearing an RF profile selection removes that mapping. Explicit policy-tag definition rows create empty tags and permit removal of unused tags; older form submissions still retain empty tags they could not represent. Off-topology AP assignments remain preserved.

Legal names such as `constructor`, `__proto__`, `toString` and `hasOwnProperty` are stored and read as own dictionary entries. They can name WLANs, policies, tags, RF/AP/Flex profiles and dot1x lists without becoming inherited JavaScript members. GUI Apply, CAPWAP, actual client forwarding and saved topology reload preserve them. Missing references with those names still reject or deactivate service.

Concurrent changes introduced a read-only AP controller diagnostics view, WLC RF channel selection, WLC profile authority over effective radios and reference dropdowns for existing/unsaved profiles and tags. This audit preserved them. A selected RF profile supplies effective enabled/power/width settings and an explicit channel; Auto uses the existing radio channel.

The follow-up audit reproduced incorrect Disabled labels for enabled profiles: status selectors were mistakenly read as checkboxes. Labels now read `on`/`off` for selectors and checked state for checkboxes. It also corrected an implicit-default mismatch: an Enterprise WLAN using the available `default` dot1x list now displays that selection. Unrelated Apply preserves implicit authentication and AKM/WPA2 defaults so the runtime does not restart an established client merely because equivalent defaults became explicit. Missing or incompatible references retain their requested value, block Apply and reveal the relevant tab/control; the GUI never silently substitutes another profile.

APs have no manual power control or local-adapter selector. A direct operational PoE allocation is required. Port Never, insufficient budget/limit, unplugging and switch power loss stop the AP and immediately remove its station associations. The WLC learns an unannounced AP loss through expiration of delivered CAPWAP heartbeats, rather than inspecting the AP's global power flag. Restoring PoE restarts addressing/join. A CLI reload restarts AP runtime without interrupting electrical allocation.

PoE high/low priority changes actual allocation under a limited budget. High priority is admitted before low priority; equal priorities follow actual detection order. Shedding removes real AP power/client service. The default and `no` form restore low priority, and the value persists with interface configuration.

Laptop settings use the same adapter and association state as Windows `netsh wlan`. Wireless frames reuse shared ARP/IPv4/IPv6/DHCP/DNS/HTTP/ICMP paths. Actual Wireless0 packet and byte counters now update in both central and local switching modes. RF/estimated data rate remain deterministic abstractions.

`tests/wireless.test.ts` adds WF-01 through WF-22. They exercise mixed central/local FlexConnect outage and recovery, incomplete profile dependencies, RF band rejection, site-profile rejoin, actual AP CLI reload, malformed saved state, RADIUS retransmit/failover/reject/cancellation, non-destructive GUI drafts, GUI-driven CAPWAP/radio/session changes, heartbeat-based AP loss detection, assignment removal, adapter counters, WLAN ID rejection, hidden SSIDs/session expiry, DNS/SSID form correctness, inherited-name dictionary safety through packet delivery and save/load, and preservation of an established Enterprise association across an unrelated GUI Apply.

The latest targeted run passes 69 tests: 48 wireless, eight AP controller and 13 PoE tests, recorded in `.cache/wlc-reference-targeted-node-tests.log`. WF-22 asserts the actual association start time and RADIUS request count remain unchanged after hostname-only Apply, then verifies delivered client ping. AP controller cases also cover received radio authority, delayed CAPWAP edits, diagnostic HTML, missing dependencies, RF channel validation and explicit empty-tag/reference behavior. This is a focused scope, not the parent task's entire regression suite.

The latest [WLC reference browser evidence](wlc-reference-browser-validation.json) passes 14 checks and [AP controller browser evidence](ap-controller-browser-validation.json) passes eight, both with no page errors. Each record includes the captured standalone HTML digest/size, relevant source digests, temporary localhost URL and fixture description. They verify unsaved/empty tag creation and deletion, keyboard tabs, status-rich dropdowns, band filtering, invalid-reference preservation/reveal, implicit-default authentication, actual CAPWAP configuration, credentials and delivered routed DNS/HTTP.

The earlier [wireless browser evidence](../testing/wireless-browser-results.json) records 21 broader checks, including AP/laptop IPv6 validation, roaming and PoE loss/recovery, against its recorded run. Neither browser inventory covers every diagnostic/field boundary or replaces a real Cisco runtime comparison.

## Required functionality still absent or partial

The current five-page form does not implement Cisco's full management/security/monitoring Web GUI. Missing areas include controller AAA/RADIUS/TACACS administration pages, HTTPS/certificate trust management, wireless ACL/QoS editors, NTP/SNMP/syslog GUI administration, client exclusion/disconnect actions, RADIUS accounting/CoA, AP authorization and image workflows, detailed radio management/RRM, mobility groups and controller failover, and save/reload GUI workflow. Shared console or service behavior is not counted as an implemented GUI page.

The confirmed removal of server TFTP/SCP/SFTP services and their GUI is an explicit project exclusion, not an outstanding addition in this WLC audit. The restored older sandbox remains reference material.

WPA3/SAE, EAP-TLS/PEAP, binary 802.11 interoperability/AES-CCMP encryption, DTLS certificate validation, autonomous APs, 6 GHz, DFS/regulatory behavior, RF contention/retries, and inter-controller mobility remain unsupported. Existing local Flex sessions survive a controller outage, but new standalone authentication is not implemented. RADIUS failover is sequential after request timeouts; persistent dead-server criteria, load balancing and separate authorization servers are not implemented. PoE reserves 30 W for a full-feature AP; 802.3af reduced-function mode, 802.3bt, physical detection/classification and fault negotiation remain absent. No unsupported mode is advertised as working.

Cisco's default-policy-tag automatic WLAN 1–16 mappings differ from this simulator's editable teaching mapping. The difference remains explicit; this audit does not claim default behavior parity. Exact prompt/output fixtures from a real 17.12 controller have not been captured.
