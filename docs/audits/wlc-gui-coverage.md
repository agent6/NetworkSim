# WLC, AP, laptop, and PoE GUI coverage

Audit date: 2026-10-17 UTC. Reference profile: Catalyst 9800 IOS XE Dublin 17.12.x; Catalyst 9115 lightweight inspired AP; explicit generic standalone AP; generic 24-port PoE+ switch. These are teaching profiles, not Cisco firmware.

The reproducible [field inventory](wireless-gui-inventory.json) is generated by `node scripts/audit-wireless-gui.mjs`. It extracts every named field template from the wireless and PoE forms, including repeated port fields and the AP assignment key, and separately inventories the AP's read-only controller displays. Each entry identifies the input, default, validation, parser, persistent state, operational/packet dependency, and relevant test evidence. Source hashes make stale extraction visible.

All 143 configuration field templates have source-to-runtime traces, including read-only existing IDs/built-in names and the hidden AP assignment key. Seventeen are profile/interface/ACL/QoS reference dropdowns; administration adds its own existing-object selectors and validated named references. The hidden `policy-tag-definitions`, `wlc-administration` and `local-original` markers preserve older form compatibility and are inventoried separately from persistent configuration. Fields remain classified **partial** under the task's strict eight-level definition: every input does not yet have a complete boundary, default, negation, reload, browser and Cisco hardware comparison matrix. These counts describe the implemented teaching surface, not the entire Cisco Web GUI.

The controller form validates an isolated draft through `IOSSession` before committing. It preserves properties not represented by the form, including disabled AKM/WPA2 flags, AP join descriptions and Flex VLAN dictionaries. RF channels now have their own represented control. Clearing an RF profile selection removes that mapping. Explicit policy-tag definition rows create empty tags and permit removal of unused tags; older form submissions still retain empty tags they could not represent. Off-topology AP assignments remain preserved.

Legal names such as `constructor`, `__proto__`, `toString` and `hasOwnProperty` are stored and read as own dictionary entries. They can name WLANs, policies, tags, RF/AP/Flex profiles and dot1x lists without becoming inherited JavaScript members. GUI Apply, CAPWAP, actual client forwarding and saved topology reload preserve them. Missing references with those names still reject or deactivate service.

Concurrent changes introduced a read-only AP controller diagnostics view, WLC RF channel selection, WLC profile authority over effective radios and reference dropdowns for existing/unsaved profiles and tags. This audit preserved them. A selected RF profile supplies effective enabled/power/width settings and an explicit channel; Auto uses the existing radio channel.

The follow-up audit reproduced incorrect Disabled labels for enabled profiles: status selectors were mistakenly read as checkboxes. Labels now read `on`/`off` for selectors and checked state for checkboxes. It also corrected an implicit-default mismatch: an Enterprise WLAN using the available `default` dot1x list now displays that selection. Unrelated Apply preserves implicit authentication and AKM/WPA2 defaults so the runtime does not restart an established client merely because equivalent defaults became explicit. Missing or incompatible references retain their requested value, block Apply and reveal the relevant tab/control; the GUI never silently substitutes another profile.

APs have no manual power control or local-adapter selector. A direct operational PoE allocation is required. Port Never, insufficient budget/limit, unplugging and switch power loss stop the AP and immediately remove its station associations. The WLC learns an unannounced AP loss through expiration of delivered CAPWAP heartbeats, rather than inspecting the AP's global power flag. Restoring PoE restarts addressing/join. A CLI reload restarts AP runtime without interrupting electrical allocation.

The same AP node now offers an explicit **generic standalone teaching profile**, distinct from C9115 lightweight firmware. Local Open/WPA2-personal SSIDs bind to selected radios, require open-system authentication and the WPA2 VLAN cipher when secured, and bridge real client frames through the configured access/native or tagged VLAN. It requires no WLC or AP management address for local client service. Its GUI validates local SSID/VLAN/security/radio settings transactionally; native `dot11 ssid`, `interface Dot11Radio0/1`, radio SSID/AES binding and `show dot11 associations` use the same operational state. An existing SSID with no radio attachment remains explicitly Unattached on Apply. Asymmetric native cipher settings use Keep existing per-radio ciphers, and unrepresented cipher VLAN entries are preserved. Changing to lightweight removes local advertisements and requires CAPWAP. Reload retains the selected operating profile and PoE supply while restoring saved settings or clearing unsaved local SSIDs. Full autonomous IOS BVI/subinterface/bridge-group firmware is outside this bounded model.

PoE high/low priority changes actual allocation under a limited budget. High priority is admitted before low priority; equal priorities follow actual detection order. Shedding removes real AP power/client service. The default and `no` form restore low priority, and the value persists with interface configuration.

The default 30 W allocation provides the four-stream teaching profile. Explicit port limits of 15400–29999 mW provide a 15.4 W 802.3af profile with two streams and USB disabled. The wireless engine consumes the allocation: the estimated rate and actual scheduled data-delivery rate halve, while management, association and data service remain operational. AP diagnostics show effective stream count. Analog classification and measured hardware performance are not simulated.

AP MAC authorization now gates actual CAPWAP join using a native credential-download method list and local Ethernet-MAC records or delivered RADIUS requests. Explicit Access-Reject stops the group, unavailable requests retry/fail over, and AP/controller power or AAA configuration changes cancel an old attempt. Completed results are reused only briefly for duplicate join retries: a later controller-loss/rejoin rechecks the live remote database. GUI monitoring reports received authorization results, including cancellation.

WPA3 personal runs a logical SAE commit/confirm exchange before association and the four-way key handshake. A wrong password fails confirmation before EAPOL/data authorization. Pure SAE requires PMF; transition mode admits legacy WPA2 clients under optional PMF while SAE clients require PMF capability. Associations store the negotiated WPA2 or WPA3 mode, which appears in Windows netsh and native client detail. Native export, startup reload and project persistence retain the configuration. The SAE confirmation implementation is a teaching proof with per-session nonces; it does not implement elliptic-curve SAE, H2E, AES-CCMP or wire interoperability.

Laptop settings use the same adapter and association state as Windows `netsh wlan`. Wireless frames reuse shared ARP/IPv4/IPv6/DHCP/DNS/HTTP/ICMP paths. Actual Wireless0 packet and byte counters now update in both central and local switching modes. RF/estimated data rate remain deterministic abstractions.

## Required functionality still absent or partial

The seven-section form covers the workflows above. It does not implement Cisco's entire management/security/monitoring Web GUI. Remaining areas include certificate trust/image workflows, creation editors for ACL/QoS definitions and SNMPv3 views/identities, wireless-specific RADIUS accounting/CoA and persistent client exclusion, detailed RRM, mobility groups and controller failover. Existing shared console capabilities are not counted as GUI pages. Unsupported physical queue actions cannot attach to wireless policy profiles.

The confirmed removal of server TFTP/SCP/SFTP services and their GUI is an explicit project exclusion, not an outstanding addition in this WLC audit. The restored older sandbox remains reference material.

Real cryptographic SAE/H2E, WPA3 Enterprise/OWE, EAP-TLS/PEAP, binary 802.11/AES-CCMP interoperability, DTLS certificate validation, full autonomous firmware, 6 GHz, DFS/regulatory behavior, RF contention/retries and inter-controller mobility remain unsupported. Existing local Flex sessions survive a controller outage, but fresh Flex authentication without the controller remains unsupported; the separate generic standalone profile supports fresh local Open/WPA2-personal clients. RADIUS failover is sequential after request timeouts; persistent dead-server criteria, load balancing and separate authorization servers are not implemented. PoE supports the two bounded power/stream profiles above; 802.3bt, analog detection/classification and fault negotiation remain absent. No unsupported mode is advertised as interoperable.

Cisco's default-policy-tag automatic WLAN 1–16 mappings differ from this simulator's editable teaching mapping. The difference remains explicit; this audit does not claim default behavior parity. Exact prompt/output fixtures from a real 17.12 controller have not been captured.
