# Protocol design and evidence

This is an original implementation. Public protocol specifications and public Cisco documentation inform behavior; no Cisco program code, firmware, images, or assets are embedded. The simulator is an educational model, not an IOS emulator or a claim of complete CCNP feature fidelity.

## Engine boundary

The data plane owns frame transmission, queues, MAC learning, ARP, route lookup, TTL, ICMP, and transport/application delivery. The control plane discovers eligible neighbors over operational broadcast domains and derives tables. A topology path alone never means a ping or application succeeded: packets must traverse the data plane, and replies need a return route.

All timers use simulated time. Configuration changes recompute control-plane eligibility. Timed port transitions are cancelled by generation checks after subsequent topology changes. An inspectable event explains state changes. Packet animation and UI filters do not govern protocol correctness.

## Ethernet and egress queue boundaries

Operational trunk/VTP/bundle state is prepared before connected routes, then reconciled again with control-plane guard changes. The first active routed bundle member installs its connected RIB in the same recompute; inactive physical members do not suspend a compatible active group.

Copper interfaces now distinguish automatic negotiation from explicit speed configuration. Fixed incompatible speeds remove carrier and connected routes. Automatic 10/100 parallel detection uses half duplex against a fixed peer; negotiated speed feeds serialization, default routing bandwidth/STP costs, storm-control load and interface output. EtherChannel compares negotiated peer characteristics and RSTP consumes operational half-duplex shared-link state. CDP advertises actual duplex; a mismatch diagnostic requires a received advertisement, and show output uses cached received values. Mismatched duplex damages frames only when opposing transmissions actually overlap. The half side records collisions and late collisions after the 512-bit slot; the full side records CRC/input errors. Matching half-duplex peers use deterministic shared-medium arbitration. This is a teaching model without FLP encoding, master/slave negotiation, exponential backoff, calibrated attenuation, cable length/pinout faults or fiber modules. Old documents with no speedAuto field preserve 1000 as automatic and other configured speeds as fixed; old explicit 1000 settings cannot be distinguished retrospectively.

Physical Ethernet output policies now enqueue actual frames before the serializer. Byte-weighted class scheduling consumes bandwidth reservations; one strict-priority LLQ can overtake waiting frames but cannot interrupt a frame in flight. Average shaping delays eligible departure times; queue-limit causes real tail drops. Output counters distinguish matched/admitted packets from dequeued transmissions. Classification is retained before an egress DSCP rewrite. Queue depths, drops and dequeue counts come from those actual queues. Policy/port/runtime changes flush pending queues and cancel their timers.

The scheduler supports up to 64 router classes (including class-default), eight Catalyst queues, 1–4096 queued packets per class and 16,384 total pending frames per port. These are simulator limits. A class shaper meters IP bytes with one initial packet and no modeled burst/overhead options. LLQ uses a 200 ms token allowance, at least 1500 bytes, enforced only during congestion. It does not reproduce Cisco hardware quanta or every release's default token bucket. Per-flow fair-queue, WRED, hierarchy and logical/input/CoPP queueing remain unsupported and reject at configuration/attachment. Imported legacy unsupported settings remain visible, fail closed with an explicit diagnostic when attached, and must be removed or replaced before CLI replay. Catalyst policies reject mixed bandwidth types and bandwidth+shape in one class; their remaining-percent values are relative weights and may total above 100, matching the selected guide. Queue telemetry includes actual link-control frames in class-default; IP classification counters remain IP-only. Marking/policing and Catalyst physical/SVI input precedence remain independent of queueing.

## Scope accounting

Each implemented control-plane feature publishes a capability description in its module. Computed convergence is distinguished from packet-level protocol exchanges. Configuration acceptance by the CLI does not imply full protocol fidelity. Unsupported options must be identified rather than silently treated as effective.

## Implemented control-plane coverage

The distinction below is part of the product contract. **Traffic** means a message traverses simulated frames, queues, links and relevant IP forwarding; it does not mean binary wire-compatible protocol encoding. **Computed** means configuration and eligible topology produce state immediately or after explicit simulated timers. Computed routing tables still require every application packet and reply to traverse the data plane. A dropped packet never becomes successful because a graph contains a path.

Configuration changes initiate recomputation, but OSPF received LSDB state, EIGRP Hello/DUAL state, RIP update timers and BGP persistent sessions determine when the corresponding routes become usable. BFD supplies an additional actual packet-based failure signal. Ordinary EIGRP route-vector advertisements and selected switching/election behaviors remain computed. These differences are visible capability boundaries, not claims of complete router protocol FSMs.

Configured IPv6 addresses remain visible during duplicate-address detection. Tentative or duplicate addresses are excluded from control-plane source endpoints and originated prefixes as well as data-plane local/connected routes. A unique replacement becomes eligible only after DAD and, for a remote OSPF observer, delivery of its replacement LSA.
