# Windows networking CLI audit

Reference profiles: **Windows 11 24H2** for PC/Laptop and **Windows Server 2025** for Server. NetworkSim implements a networking subset. No Windows kernel, executable, registry, PowerShell, process manager, NetBIOS, WINS, or Windows service-control manager runs here.

The shared parser is `src/windows-cli.ts`. The public `IOSSession` facade delegates all three host kinds to it before IOS parsing, uses `C:\>` for all three, and keeps remote Cisco terminal sessions separate. `main.ts` polls continuous output and keeps input read-only while `ping -t` runs; Ctrl+C cancels it. Laptop wireless commands use the same adapter configuration and wireless state machine as Laptop settings.

## Inventory and evidence

`windows-command-inventory.json` records **17 automatically extracted root spellings and 44 audited command-family variants**: **5 complete narrow local/alias behaviors, 36 partial supported networking subsets, and 3 unsupported/legacy entries**. These are not 44 distinct Windows executables. “Partial” means functional tested behavior exists but the full Microsoft option/output/platform contract remains wider. No native Windows golden transcript was captured. Documentation-derived syntax/default facts are stored separately in `fixtures/windows-reference-v1.json`; they are not presented as native output fixtures.

Regenerate locations and source digest with `node scripts/audit-windows-commands.mjs`. Parser roots are automatically extracted from every `command === '...'` dispatch comparison. Variant records explicitly include the original host paths, additions, legacy alias and unsupported requested families. The repository-wide command inventory is a separate artifact.

## Server GUI integration

`services-ui.ts` remains an explicit NetworkSim service administrator; it does not claim to be Windows Server Manager. DHCP input validation rejects host bits in network addresses, gateways outside their pool, reversed exclusions and fractional leases before committing any changes. The existing duplicate-pool validation remains. Syslog displays received packet source, hostname, timestamp, facility and severity; local device logs are no longer substituted for received messages. DHCP lease lookup reads actual server leases and updates without discarding unsaved form edits.

The user explicitly approved retaining the recent removal of server TFTP and SCP/SFTP services and their administration pages on October 16, 2026. The desktop File Transfer client is also removed. Older file dictionaries are retained, while server listeners are disabled on load/reload and reject requests even if old enabled flags remain. Tests in `services-ui.test.ts` cover this exclusion alongside DHCP validation and received Syslog metadata. DNS, HTTP, RADIUS/TACACS+, NTP, DHCP and Syslog continue through shared packet handlers. The separately added passive IPv4 Server FTP service is visible as a TCP21 listener only while enabled; FTPCLI-05 verifies that view against actual service configuration. AAA accounting has separate VTY delivery and browser evidence in `aaa-accounting-fidelity.md`.

## Remaining limitations

- Windows command/output equivalence is documentation reviewed; no native Windows 11/Server 2025 comparison session was available. Formatting is an original Windows-style projection of simulator state.
- `ping -n` is bounded to 100 per command; size is 0–65500 data bytes, timeout 1–60000 ms. Traces are bounded to 64 hops. Many optional Windows source-route/reverse-route/OS-specific flags are unsupported.
- Tracert performs delivered reverse PTR queries unless `-d`; pathping does so unless `-n`. Missing/blocked PTR queries leave numeric addresses. Pathping samples one discovered hop at a time and reports source-to-hop loss only, without Windows per-link loss attribution or background multitasking. It cannot distinguish a router refusing ICMP from forwarding loss.
- `ipconfig /autoconfig6` is retained solely for older lab compatibility, emits an explicit non-Windows notice, and is omitted from supported Windows help. `/release6` now sends/retries actual DHCPv6 release and removes only leased resources. A failed remote reply reports failure without claiming the server reclaimed its binding. DNS registration, DHCP class IDs and adapter compartments are unsupported. An unaddressed legacy manual PC can request its initial DHCP lease; this is a compatibility choice.
- IPv4 route change supports next-hop, metric and selected-interface updates of a uniquely matched user route; persistence follows the existing route. IPv6 netsh route add/set/delete supports selected prefixes, adapters, next-hops, metrics and active/persistent stores. Connected-route deletion, automatic Windows metrics, overlapping-store shadowing, finite route lifetimes and route advertisement are outside the subset. The portable lab file supplies persistence; no host registry is touched.
- Netstat does not invent process IDs, executable names, OS sockets or protocol statistics. `-n` uses numeric addresses in both modes; reverse endpoint name lookup is pending. `getmac` uses simulator transport labels rather than native Windows adapter GUIDs.
- Netsh supports the explicitly listed address/DNS/admin subset. It does not rename physical engine interfaces or model Windows network compartments, WINS, proxies, Teredo/6to4, firewall rules or every command option. Static IPv6 address storage is persistent only; active-only address storage and finite address lifetimes explicitly reject. DNS validation is not a native Windows asynchronous validation workflow.
- Wireless profiles originate in Laptop settings/current preference and stored simulator profiles. Native profile XML import/export, Windows profile priority/group policy, native SAE cryptography, OS WLAN reports and multiple WLAN adapters are unsupported. A successful connect message acknowledges a **request**; runtime association/security/DHCP must still succeed.
- NetBIOS/NetBT is unimplemented; `nbtstat` reports this explicitly. Server service administration uses the GUI rather than invented Windows commands. Full OS authorization is outside this networking subset.

## Browser validation

`windows-browser-validation.json` records 16 passing checks in isolated headless Chrome, opening the standalone HTML directly from disk and importing a fixture through the public YAML workflow. The run verifies continuous ping streaming/input locking/Ctrl+C, typed DNS GUI-to-query integration, SNMPv2c/v3 manager success and invalid identities, invalid DHCP/DNS rollback, the file-service exclusion, real Windows DHCP acquisition, and CLS clearing with retained history. Screenshots are in `.cache/windows-browser/`. The separate server browser checks cover accessible service tabs and live DHCP lease lookup. This supplements the original 21 Windows behavioral tests; WIN-22–29 add route, PTR, IPv6 addressing/routing and DHCPv6 release packet tests; it does not establish native Windows output equivalence.

Windows echo replies now originate with TTL/hop-limit 128 for PC/Laptop/Server; an intervening router decrements the delivered value. WIN-21 verifies IPv4 and IPv6. Sources: [Microsoft IPv4 protocol defaults](https://learn.microsoft.com/en-us/powershell/module/nettcpip/set-netipv4protocol?view=windowsserver2025-ps) and [IPv6 protocol defaults](https://learn.microsoft.com/en-us/powershell/module/nettcpip/set-netipv6protocol?view=windowsserver2025-ps). Cisco node defaults and other protocol initial hop limits remain a separate fidelity item.

This is a bounded Ansible-compatible teaching subset for CCNA v2.0 objective 5.5, not an Ansible installation.
