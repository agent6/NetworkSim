# Wired routing and switching fidelity audit

This audit distinguishes working packet behavior from computed protocol models and stored configuration. It is not certification of every IOS command or complete CCNP coverage. The automatically extracted repository inventory is the command coverage index; the rows below record the wired subsystem trace and concrete implementation findings. No proprietary implementation code was copied.

The primary switching references are Catalyst 9300 IOS XE **17.12.x**. Routing references use Cisco's IOS XE **17.x** guides; exact release-specific behavior without a 17.12 device observation remains unverified. Packet Tracer is secondary evidence and was not used to override these references.

## Repairs and independent regressions

| Finding | Corrected implementation | Packet evidence |
| --- | --- | --- |
| Physical switch service policies accepted configuration but bridged frames bypassed QoS | `engine.ts` applies physical ingress/egress policies to bridged IP frames on L2, L3 and PoE switches; actual selected EtherChannel members use the same hooks | `tests/wired-fidelity.test.ts`: UDP succeeds before policy, fails on input/output drop, and recovers after removal; member marking changes received DSCP |
| VLAN input marking did not affect bridged frames, and a physical hook could double-charge SVI traffic | Physical policy takes precedence over SVI marking; an ingress marker prevents a second logical input evaluation | Same suite: actual received DSCP, exact per-port/VLAN counters, locally delivered SVI echo and fallback after removal |
| Directly transmitted routed multicast/broadcast control messages bypassed output QoS | `sendControlDatagram` evaluates output policy before direct transmission | Same suite: actual OSPF/EIGRP control drops expire peers and withdraw routes; unaffected connected ICMP still works; removal restores routed echo |
| `match ip address ACL` was accepted but never matched in routing policy | `applyRouteMap` evaluates standard network and extended network/mask ACL semantics | Same suite: actual BGP UPDATEs retain only permitted routes; standard/extended filters change real bidirectional UDP; removal restores advertisements |
| VTPv1/v2 accepted equal revisions, did not increment local edits, excluded client-originated higher revisions and server adoption, copied extended VLANs, and retained stale revision when the payload was unchanged | Local server database edits advance revisions; strictly newer matching databases can be adopted from server/client peers; normal-range synchronization preserves local extended entries; unchanged payload still advances the received revision | Same suite: both protocol versions, CLI VLAN rename/delete, higher client revision, equal-revision conflict, extended VLAN isolation, real VLAN UDP delivery and failure after deletion |
| Routed EtherChannel compared local VRF names across peers | Channel negotiation ignores peer VRF names while still checking local member consistency | Same suite: BLUE/RED locally named routed LACP groups establish and carry UDP; wrong local VRF fails |
| Routed channel members processed ARP as both individual interfaces and the aggregate, producing competing member MAC replies | Routed bundle ingress is delivered to its logical aggregate | Same suite and existing `core.test.ts` routed hashing tests: correct neighbor resolution, bidirectional flow and member hashing |
| IPv6 BGP AF and UPDATE attributes were unsupported | Independent IPv4/IPv6 AF configuration and activation, negotiated logical capabilities, native IPv6 TCP transport, family-specific NLRI/next-hop validation, shared transport, policy, show output, rendering and VRF-Lite | `tests/bgp-multiprotocol.test.ts`: native IPv6 TCP data, ND and UDP; family filtering; actual withdrawals; activation removal; config replay/reload; overlapping BLUE/RED neighbor and prefix isolation |
| BGP `maximum-paths` was accepted but installed only one route; IGP cost was omitted from path ordering | Eligible eBGP/iBGP equal paths install actual ECMP; real IGP next-hop cost precedes router ID and limits multipath eligibility | Same suite: 60 delivered UDP flows use both installed next hops; link failure leaves one working path; OSPF cost chooses the higher-router-ID peer with the shorter IGP path |
| IPv4 and IPv6 prefix lists shared one destructive sequence namespace and rendered IPv6 entries as IPv4 | A compatible combined store keeps independent per-family sequence, removal and auto-numbering behavior; render/show commands select the correct family | Same suite: identical list name and sequence filter different AFs, independent removal and replay |
| Dual-stack BFD deduplicated interfaces across address families; IPv6 BGP could not associate a global peer with its link-local BFD session | Independent IPv4/IPv6 sessions; global IPv6 peers bind to the actual on-link neighbor's link-local BFD session | Same suite: real BFD control loss withdraws IPv6 BGP before its hold timer while connected IPv6 ICMP remains operational; restoring control packets restores routed UDP |
| A newly operational routed EtherChannel could have no connected route until an unrelated later recompute; a down unused member could suspend an otherwise compatible group | Operational link/trunk/VTP/channel state is prepared before connected routes; later control reconciliation remains; local operational member checks exclude physically down members | `tests/ethernet-physical.test.ts`: first one-member bundle installs its connected route immediately, carries real ICMP, withdraws on disconnect and restores on reconnect; VTP revision tests verify no duplicate increments |
| Fixed speed mismatch kept carrier up, automatic/explicit 1000 Mb/s could not persist independently, and duplex had no traffic effect | Copper negotiation determines carrier, actual speed and duplex; real opposing transmission overlap causes half-side collision/late-collision, full-side CRC, and actual frame loss; operational speed feeds routing/STP/default bandwidth and storm-control measurements | `tests/ethernet-physical.test.ts`: carrier/connected-route withdrawal and recovery, config replay, parallel detection, exact error direction, mismatch correction, matched half-duplex arbitration and actual OSPF metric/ICMP, negotiated LACP compatibility, shared RSTP timing and packet-delivered CDP diagnostics |
| Queue reservations, priority, shaping and queue-limit were accepted without scheduling effects | Physical output policies use actual event-clock class queues, byte-weighted fair scheduling, congestion-limited LLQ, average-rate shaping and tail drop; pre-mark classification survives egress marking; admission and dequeue counters are separate | `tests/qos-scheduler.test.ts`: unequal-size 25/75 byte shares, priority ordering, exact delivered/drop counts, measured shaping spacing, priority exceed drops, removal/flush/recovery, L2/L3/PoE bridging, Catalyst relative-weight semantics/limits and fail-closed unsupported import |

| EIGRP IPv4 `auto-summary` accepted configuration without changing routes; summaries without an explicit metric used zero | Classic router and named IPv4 topology commands now suppress specifics across classful boundaries, conditionally install AD5 Null0 routes and use the minimum live component metric. External-only components stay specific until an internal component in their major network permits aggregation; resulting advertisements are internal summaries. Modern default/no/default forms disable automatic summarization; IPv6 rejects it | `tests/eigrp-auto-summary.test.ts`: classic/named discontiguous failure and recovery with actual ICMP, same-major specificity, component metric changes and last withdrawal, external server echo through an intermediate summarizer, VRF isolation, topology/protocol output, help, replay and reload |

CoPP did not require a forwarding repair: OSPF and EIGRP already use logical IP packets delivered through `receiveIP` and its control-plane policy. The added regression verifies actual adjacency loss, counters and recovery. STP/CDP/LLDP/UDLD are separate link-control envelopes and do not claim IP CoPP coverage.

## Remaining subsystem scope and limitations

Every row marked partial remains partial even where its existing regression suite passes. These are implementation boundaries, not claims that every listed limitation occurs in every exam task.

| Subsystem and source | Operational trace / tests inspected | Status and remaining limits |
| --- | --- | --- |
| Ethernet/VLAN/SVI, `ethernet.ts`, `engine.ts`, `ios-switching-compat.ts` | Negotiated carrier/speed/duplex → actual serialization and traffic-driven errors; VLAN/STP/security admission → MAC learning → SVI routing; physical/core/switching/PoE/wired regressions | Bounded copper model. No FLP/master-slave signal exchange, binary exponential backoff, PHY waveform, calibrated attenuation, cable length/pinout faults or fiber transceivers. Matching half duplex uses deterministic shared-medium arbitration. No finite hardware MAC/TCAM resource model; tagged aggregate subinterfaces are not covered by the routed bundle test |
| STP/RSTP/MST, `control-plane.ts` | Per-VLAN roles/costs and transition timers; actual heartbeat loss for loop guard; topology/compatibility tests | Computed root/role election; no complete received-BPDU election/proposal/agreement or CIST region-boundary FSM; UplinkFast lacks MAC-update packets |
| DTP/VTP, `control-plane.ts` | Negotiated trunk state → domain/revision database adoption → actual VLAN forwarding | Computed rather than packet FSM; VTPv3 primary-server behavior and VTP pruning absent; transparent version-specific advertisement handling not exhaustively validated |
| EtherChannel/LACP/PAgP, `control-plane.ts`, `engine.ts` | Local/peer compatibility → active/standby members → actual single-member frame/hash forwarding | Computed negotiation, no wire PDUs; no independent member congestion scheduler; asymmetric peer allowed-VLAN/native-VLAN consistency has not been certified against the selected platform |
| Static routing/CEF/VRF, `route-resolver.ts`, `engine.ts` | Connected/static RIB → recursive weighted forwarding paths → ARP/ND → actual packets; resolver/reference/VRF suites | Original deterministic hashing, not a hardware ASIC reproduction; bounded recursion. Control-plane consumers outside BGP still contain a separate `resolveEgress` helper and need further edge-case parity review |
| OSPFv2/v3, `ospf-packets.ts`, `control-plane.ts` | Actual Hello/DBD/LSREQ/LSUPDATE/LSACK and received LSDB → SPF/RIB; loss, timers, AF, NSSA and virtual-link tests | Logical router records, not full area-scoped RFC LSA-type databases. DR election and area adapters are computed; complete NBMA/wait and NSSA translator/P-bit/forwarding-address FSMs absent |
| EIGRP, `control-plane.ts` | Actual Hello/hold and reliable QUERY/REPLY/ACK/SIA gate computed vectors, feasibility and ACTIVE/PASSIVE; classic/named IPv4 classful/manual summaries and conditional minimum-metric discards affect real traffic; routing/VRF/control/auto-summary tests | Normal UPDATE advertisements remain computed. No complete RTP/DUAL input matrix or control bandwidth pacing; bounded numerical wide metrics and external scalar seed propagation. Manual-versus-automatic summary overlap and every external vector corner case are not certified against a selected-release device |
| RIP/RIPng, `control-plane.ts` | Actual periodic/triggered advertisements, policies, poison/aging and RIB; loss/version/timer tests | Single selected route, no ECMP or full request-response exchange; queue/flash threshold knobs are stored only |
| BGP, `bgp-session.ts`, `bgp-compat.ts`, `control-plane.ts` | Actual persistent TCP and negotiated IPv4/IPv6 unicast → received Adj-RIB-In → policy/best path/ECMP → RIB/UPDATEs | Logical MP capability/UPDATE envelopes. Capability changes reset the session. No binary encoding, MRAI, graceful restart, confederations, VPN/multicast SAFIs or full collision/event matrix. Explicit IPv6 link-local neighbor zone syntax and extended next-hop capability are unsupported. The 65-second reboot regression follows existing keepalive/retry detection; complete simultaneous-open behavior remains simplified |
| Prefix lists/route maps/redistribution, `control-plane.ts`, `packet-policy.ts` | Address-family-aware prefix policy, standard/extended routing ACLs, ordered deny/set/continue, PBR next-hop selection; policy/redistribution tests | Bounded IOS policy language. Repeated same-category match command merging, bare removal forms and all unsupported match/set combinations still need explicit per-command reconciliation |
| ACL/PBR/NAT, `packet-policy.ts`, `engine.ts` | Ingress ACL → inbound NAT → local/control delivery or route/PBR → outbound NAT/QoS/ACL → wire; policy/core suites | Modeled packet fields and bounded NAT/PBR catalog; no full IOS ACL/message set, NAT ALG or exhaustive noninitial-fragment hardware behavior |
| L2 security/IPv6 FHS, `packet-policy.ts`, `fhs-tracking.ts` | Actual ingress DHCP/ARP/ND/IP → binding/rate/guard policy → permit/drop and counters | Structured fields, not raw packet-byte validation or every platform hardware feature; resource/attack behavior is bounded |
| QoS/CoPP, `packet-policy.ts`, `qos-scheduler.ts`, `engine.ts` | Actual classification, marking/policing, physical/L3/control drops; physical output CBWFQ/LLQ/shaper queues with real delivery timing and congestion counters | Bounded byte-weighted scheduler, not a Cisco ASIC recreation. Physical Ethernet output only, one priority class, maximum 64 router classes/eight Catalyst queues including class-default, queue-limit 1–4096 and aggregate safety limit 16,384 queued frames. Shapers allow one initial packet, meter IP bytes, and do not implement IOS burst/overhead/hierarchy options. LLQ uses a documented simulator 200 ms token allowance (minimum 1500 bytes), active under congestion. Catalyst mixed bandwidth types and bandwidth+shape conflict reject; remaining-percent weights may total above 100. Per-flow fair-queue, WRED and queueing on input/CoPP/logical interfaces reject. Older imported unsupported policies retain their configuration but fail closed with explicit diagnostics; CLI replay must remove/replace them |
| HSRP/VRRP/GLBP, `fhrp-packets.ts`, `control-plane.ts` | Actual advertisements/hold expiry → per-observer election → ARP/MAC gateway ownership → routed traffic | IPv4 model; no complete Coup/Resign, GLBP redirect/secondary-forwarder timers or IPv6 FHRP; auth compatibility is not cryptographic |
| BFD/UDLD, `control-plane.ts` | Actual link/IP controls, advertised timers and optional echo → dependency failure/err-disable; control/routing/BGP tests | Single-hop bounded state model; BFD authentication/dampening templates are stored only; demand/multihop and complete diagnostics absent |
| GRE/NHRP/DMVPN, `engine.ts`, `control-plane.ts` | Independent underlay resolution → actual logical registration/resolution → GRE inner/outer forwarding | No DMVPN Phase 3 redirect/shortcut FSM, NHS clustering or IPv6 NHRP; stored shortcut/redirect flags do not implement them |
| Multicast, `control-plane.ts`, `igmp-snooping.ts`, `msdp.ts` | Actual IGMP/PIM Register/dense controls and data; computed shared trees/DR; persistent TCP MSDP | Computed Hello/Join-Prune/Assert eligibility; no complete BSR/Auto-RP, IGMP exclude matrix, IPv6 multicast/MLD or full MSDP mesh/filter catalog |
| SPAN/NetFlow, `packet-policy.ts`, `remote-span.ts` | Actual copied frames and routed structured exports; counters follow observed packets | Logical envelopes, no wire-compatible RSPAN/ERSPAN/NetFlow encoding or arbitrary flexible record fields |
| IP SLA/tracking/keychains, `sla.ts`, `tracking.ts`, `control-plane.ts` | Actual ICMP/HTTP/UDP probes and timed object state consumed by FHRP/routes; key validity windows gate control packets | Bounded operation/track catalog; no cryptographic protocol digests. PTP election reports `synchronized=false`, not clock synchronization |
| PoE, `poe.ts`, `ios-poe.ts` | Direct enabled PSE port + budget and high/low port priority → detection-order allocation → AP power lifecycle and real client loss/recovery; PoE/wireless tests | One full-feature 30 W AP allocation with high/low priority and equal-priority detection order. No 802.3af reduced mode, 802.3bt, calibrated electrical faults or non-AP powered devices |
