# IOS-style CLI coverage and remaining parity work

This is an implementation audit of the original NetworkSim CLI, not a claim of complete Cisco IOS command compatibility. The acceptance reference is [reference-feature-inventory.md](reference-feature-inventory.md). No supplied implementation, command catalog, or asset is imported by this code.

The CLI is `src/cli.ts`, deterministic configuration rendering is `src/config-renderer.ts`, and authentication, remote terminal sessions, archives, EEM, and IP SLA scheduling are in `src/management.ts`. `IOSSession(engine, deviceId).execute(line)` is synchronous and returns `string[]`. The UI consumes `prompt`, `pageLength`, `passwordInput`, `complete(prefixThroughCaret)`, `help(prefixThroughCaret)`, and `cancel()` and `escape()` (suspend). Suspended sessions expose `show sessions`, `resume [N]`, and `disconnect [N]`.

Unknown commands fail. Handlers that declare configuration-only behavior now reject the command and restore the previous configuration. Such settings are not counted as operational support; see [CML conformance](cml-conformance.md). Operational `show` output comes from structured configuration or actual engine state. No command fabricates a successful ping, remote login, protocol neighbor, or service response.

**Datacenter Switch is a separate dialect.** `src/session.ts` selects `NSOSSession`
for `kind: datacenter` and retains IOS/host sessions for existing kinds. The
standalone NX-OS-style NS-OS grammar/help, role checks and renderer are in
`src/nsos.ts` and `src/nsos-config.ts`; IOS-only families are not aliases.
See [NS-OS capabilities, explicit feature gates, management and limitations](features/datacenter.md).
Focused evidence is in `tests/nsos.test.ts` and `tests/datacenter-vpc.test.ts`.

## Verified CLI integration evidence

The last complete checkpoint passes **299/299 tests and TypeScript checking** (`.cache/final-measured-parity.log`, 2026-10-16). The CLI/management work has **77 directly owned tests** across the six files below; independent packet and control-plane suites supply additional behavioral evidence. Later integration work must retain that distinction: a renderer test alone does not establish packet behavior.

- `tests/cli.test.ts` — 40 cases: modes and abbreviations, configuration validation and round-trip, startup/reload, IPv4/IPv6 probes, static routes, DHCP/TFTP/NTP/syslog, ACLs, security policies, routing protocols, BGP path displays, flexible NetFlow, crypto, keychains, manual IPv6 identity, extended ping, flash capacity, calendar, RSPAN/ERSPAN and FHS policies.
- `tests/management.test.ts` — 17 cases: console/enable/local and remote login, actual SSH/Telnet transport and failures, nested/suspended sessions, timeout/reboot, archives/EEM, real RADIUS/TACACS authentication and exec/command authorization, reject-versus-unavailable fallback, Type 7 compatibility, terminal monitoring, HTTP AAA, and actual HTTP/UDP-jitter SLA probes.
- `tests/tracking.test.ts` — 3 cases: delayed leaves and boolean lists, flap cancellation and cycle errors, classic STP transition deadlines, and weighted/percentage threshold hysteresis.
- `tests/discovery.test.ts` — 3 cases: delivered CDP/LLDP advertisements, directional loss and expiry, transmit/receive controls, reboot and physical-link scope before STP forwarding.
- `tests/fhrp-packets.test.ts` — 3 cases: HSRP version/authentication compatibility and restoration, one-way Hello loss, advertised hold expiry, and VRRP/GLBP packet liveness. Control-plane tests independently cover delayed preemption and per-observer elections.
- `tests/reference-closure.test.ts` — 11 cases: permanent/tracked static route withdrawal and recovery; DHCP release reaching the server and canceling renewals; explicit RA prefix flags, preferred/valid lifetime expiry, solicited response under RA suppression, and default-route AD2; DHCP router defaults, floating RIB selection, secondary IPv4, static DAD, SLAAC lifetime reduction, DHCPv6 offer/commit ownership, incomplete ARP and real clear-OSPF re-exchange.

`tests/control-plane-cli.test.ts` additionally configures actual BFD/OSPF, tracked gateways, NHRP/mGRE, multicast/GLBP, named authenticated IPv6 EIGRP, RIP policy and L2 guards through the CLI. Other suites test packet OSPF, persistent BGP, multicast, remote SPAN, snooping and the shared forwarding engine. Run all evidence with Node 24+: `npm run typecheck` and `node --test tests/*.test.ts`.

## Reference limitations versus broader IOS enhancements

The reference itself explicitly lacks serial transport, wireless/hardware-module workflows, LACP fast/min-links/max-bundle, complete hardware CEF/dCEF/adjacency rewrite behavior, and cryptographic interoperability. MPLS VPN, IKEv2/certificates, actual QoS queues/shaping and complete SNMP/SSO engines must not be presented as missing *reference* functionality without additional evidence. SNMP now has a read-only UDP agent with logical v3 access control and real request counters (see `audits/snmp-fidelity.md`); SSO configuration is rejected as unimplemented; PTP models election only, matching the bounded category rather than claiming hardware synchronization.

A direct source check at `network-sandbox/js/cli/commands/icmp.js:346–380` shows that the reference extended-ping prompts ignore ToS, reply-data validation, data pattern, source-route/record/timestamp and sweep answers; only DF is stored in that portion. The new implementation has stronger ToS/pattern/sweep behavior and honestly rejects unsupported IP options instead of reproducing a no-op success.

Type7 compatibility uses an original reversible codec and preserves real simulated login behavior. It is configuration obfuscation only, consistent with [Cisco's password guidance](https://www.cisco.com/c/en/us/td/docs/routers/ios/config/17-x/sec-vpn/b-security-vpn/m_sec-cfg-sec-4cli-0.html). It is not a security guarantee or a replacement for IOS secret hashes.

The browser uses a new portable format carrying structured configuration. Exported IOS-style text is designed for the supported parser; server application content, service-account data, simulated local files and scheduler runtime are not all representable as IOS command text. Persistent configuration and files remain in structured project/startup state; runtime is rebuilt as documented by the engine.

Value-bearing `no set dscp <value>` and nested `no conform-action|exceed-action|violate-action <action>` forms are accepted alongside existing bare resets. Malformed values and surplus arguments reject atomically. Three-color defaults and real drops survive action removal, save/reload and CLI replay (`qos-parity.test.ts`). Classic EIGRP `bfd interface` and named AF-interface BFD true/false settings now render and replay in the matching VRF; three independent `eigrp-bfd-persistence.test.ts` cases verify real route/echo gating and recovery. Native behavior for removal arguments differing from the current value remains unverified; standalone autonomous-system remains unavailable in named EIGRP.
