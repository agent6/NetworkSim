# Wireless interface command applicability

Checked 2026-10-17 UTC against primary Cisco references and the current simulator. This records positive documented configuration paths; it does not infer a universal hardware prohibition from missing examples.

The [Catalyst9800 IOS XE17.12 WMI guide](https://www.cisco.com/c/en/us/td/docs/wireless/controller/9800/17-12/config-guide/b_wl_17_12_cg/m_config-wmi.html) configures management with an SVI and a Layer2 uplink trunk. Its restrictions reserve direct Layer3 WMI deployment for public cloud. The examples create `interface Vlan201`, configure the uplink with `switchport mode trunk`, and select allowed management/client VLANs. The [same release's VLAN chapter](https://www.cisco.com/c/en/us/td/docs/wireless/controller/9800/17-12/config-guide/b_wl_17_12_cg/m_config_vlan_ewlc_cg.html) documents the controller VLAN workflow. These establish the supported positive alternative to router-on-a-stick configuration; they do not prove that every C9800 variant or generic IOS XE subsystem forbids physical subinterfaces.

The [Catalyst9100 AP command reference](https://www.cisco.com/c/en/us/td/docs/wireless/access_point/ios-xe/command-reference/b-cisco-cat-ap-iosxe-cr/capwap_commands.html), applicable to the lightweight family selected for the simulator, documents Ethernet tagging through privileged `capwap ap ethernet tag <0–4094>`, with zero disabling tags. Its static-address command is privileged `capwap ap ip ...`. This is a CAPWAP AP configuration model; old autonomous AP `Dot11Radio`/Ethernet subinterface guides are not evidence for the selected lightweight profile. Neither native command is claimed implemented merely because it is documented here.

In NetworkSim, the WLC has one modeled physical GigabitEthernet1 and the AP has GigabitEthernet0. Their current interface creation path does not create router-style Ethernet subinterfaces. The generic `encapsulation dot1q` handler requires a subinterface and therefore has no valid positive execution path on either ordinary wireless physical port. Help/registry exposure should be gated by the actual modeled subinterface capability/context. This is an explicit simulator-profile boundary, not a guessed Cisco native exclusion. Router subinterfaces retain their existing positive configuration and packet behavior.

The existing direct-IP WLC teaching profile also differs from the SVI/trunk appliance workflow. Full C9800 chassis/SVI integration remains a separate implementation requirement; hiding an impossible encapsulation command does not complete that work or establish native chassis parity.
