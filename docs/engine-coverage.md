# Original engine implementation and tested scope

The implementation in `src/clock.ts`, `src/ip.ts`, `src/model.ts`, `src/engine.ts`, `src/packet-policy.ts`, `src/ipv6-services.ts`, `src/tcp-channel.ts`, `src/ospf-packets.ts` and `src/crypto.ts` was written for this project. No reference implementation, Cisco binaries, firmware, assets or command catalogs are embedded. All network activity is simulated in memory. The product can run as a standalone offline HTML file; the core has no DOM or server dependencies.

This document describes actual behavior, rather than equating a command family with full Cisco IOS support. Control-plane algorithms and their narrower protocol coverage are documented separately in `protocol-design.md`.

## Behavioral limits that matter when designing labs

- This is an educational simulation, not an IOS image or a full packet-byte stack. Frames and IP/TCP/ND/DHCP payloads are structured records. Checksums, Ethernet collision/carrier physics, real sockets, hardware modules and ASIC timing are absent. Source MAC/FDB/VLAN/IP/transport decisions still determine delivery.
- A positive service/probe result requires the corresponding delivered response. Multicast `sendMulticast` success only means traffic was originated; receiver tables/events establish delivery. Unimplemented commands must report their limit.
- Unconfigured/reset CEF uses the original router-specific universal hash selector. Configured CEF algorithms include source/destination and selected transport-port keys plus seeds; their deterministic formulas are educational, not Cisco ASIC bit-for-bit hashing or per-packet balancing. EtherChannel uses the configured source, destination or combined MAC/IP key; non-IP frames fall back to the corresponding MAC key. The simulator's explicit default is `src-dst-mac`, without a claim that it matches every Cisco platform's default. CEF displays share the route resolver rather than claiming an independent hardware FIB.
- NDP uses structured solicitation/advertisement records. SLAAC uses EUI-64 /64 addresses. DHCPv6 preferred addresses are chosen before deprecated alternatives for new automatic source selection. Full RFC6724 address-selection rules, privacy addresses, full NUD states, DHCPv6 reconfigure and automatic application of a delegated prefix to downstream interfaces are not complete. SLAAC router and autonomous-prefix lifetimes, deprecation and explicit on-link routes are implemented. The RFC4862 two-hour reduction rule is implemented and multiple advertised autonomous prefixes can be installed. Full RFC6724 source selection and complete host-stack interoperability remain outside the model. Delegated prefixes are available by name for lab configuration. DHCPv4 includes NAK/decline and a delivered ARP probe before new address installation; it does not model every server-side ICMP preallocation probe strategy or guarantee conflict detection when probes/replies are lost. Client conflict retries are bounded to four candidates per request.
- IPv6 FHS consumes the named policy fields described above. Simulated ND is unsecured unless explicit model metadata says otherwise, so configured minimum security levels/drop-unsecure reject ordinary ND. SEND, cryptographic validation, every option parser and hardware device-tracking state are absent.
- TCP has retransmission, segmentation and response reassembly, but no complete congestion-control/window/SACK/urgent-data/byte-stream interoperability model. The reusable channel supplies ordered JSON messages, with one handshake and a maximum of six attempts per unacknowledged control/data segment; it does not invent idle liveness—applications supply keepalive/hold timers. Packet inspection explicitly labels modeled segment indexes rather than fabricating TCP byte sequence numbers. TFTP targets simulated text/configuration files; its modeled blocks count text units rather than general binary octets. HTTP supports modeled authentication and text/configuration files; it has no TLS, real sockets or full web-server implementation.
- NAT64, hairpinning, application helpers and complete static port-forward syntax are not implemented. Dynamic pool allocation is bounded to 65,536 addresses per allocation attempt.
- Time-range evaluation uses deterministic UTC: `2026-01-01T00:00:00Z + simulation time + configured/synchronized device offset`, unless `clockEpoch` is set. It is independent of the computer's real wall clock and does not implement arbitrary timezone/DST calendars.
- NTP models timestamp/offset/stratum behavior, preferred peers, reach registers, source selection, bounded holdover and reference-chain loop rejection. It does not model full clock discipline, statistical filtering, drift or real-world authentication. Logs use explicit simulated logging calls; not every possible IOS diagnostic produces a syslog message.
- QoS marking/policing now accompanies actual bounded physical-output CBWFQ/LLQ queues, average shaping and tail drop. Router output policies now have 16 hashed byte-fair flow queues and real precedence/DSCP WRED/ECN admission, with 14 independent packet tests. Catalyst router-syntax placement, hierarchy, byte/time/discard-class options and logical/input queues remain unsupported; numerical/default/calibration bounds are documented in `audits/qos-congestion-fidelity.md` and `protocol-design.md`. This is not hardware-exact congestion behavior. RSPAN and ERSPAN envelopes are educational structured frames/GRE records, not interoperable hardware packet formats. Flexible NetFlow supports the exposed address/protocol/port/interface/DSCP match fields and packet/byte/timestamp counters, rather than arbitrary IOS record fields. NetFlow exports structured educational records, not interoperable collector wire formats.
- IKE/IPsec/SSH authentication and encryption names are **educational labels, not cryptography**. Inner traffic remains inspectable in the event model. The IKE handshake uses deterministic compatibility tokens, not Diffie-Hellman, real authentication, encryption or wire-compatible IKE. ESP validates modeled association/sequence state but has no cryptographic confidentiality or integrity. Certificate PKI, IKEv2, NAT-T, full anti-replay window, dynamic crypto maps and production VPN interoperability are absent.
- SPF and spanning-tree calculations consume educational model state. OSPF uses packet-learned per-observer LSDBs and BGP uses persistent modeled TCP; these do not imply complete standards wire compatibility. OSPF floods modeled router records across participating areas and the companion adapter applies ABR/NSSA routing rules; separate RFC area-scoped LSA-type databases are not a complete implementation. Large OSPF records use bounded logical chunks, not IPv6 router fragmentation. Consult `protocol-design.md` for each protocol's exact scope.
- SNMP, PTP, SSO, keychain lifetimes, remote AAA and SLA belong to companion modules. Remote RADIUS/TACACS authentication and exec/command authorization, actual ICMP/HTTP/UDP-jitter SLA and weighted/delayed tracking have passing integration tests. AAA accounting remains explicitly configuration-only. Their presence in the reference family list does not establish complete IOS semantics here. The CLI/control-plane documents and tests are authoritative for their implemented subset.

## Validation evidence

The focused engine checkpoint on 2026-10-16 passes all 76 cases in `tests/core.test.ts`, including IPsec/factory boot, DHCP renewal/expiry/recovery, NAK/decline/conflict and fresh-clock reload, switching automatic clients to manual addresses, NAT aging, Option82, NTP source/loop behavior, L2 security refinements, proxy ARP, extended ICMP/throttling, scoped IPv6 link-local echo, EtherChannel hash distribution, flexible NetFlow, packet-summary redaction, persistent TCP/GTSM, explicit service sources, CEF flow hashing, advanced IPv6 FHS and logging controls. Five standalone OSPF packet tests also pass. Eleven focused reference-closure cases and eight policy-closure cases add packet evidence for the second-pass audit; see reference-engine-gap-audit.md for exact mapping. Companion coverage includes five HTTP tests, five IGMP snooping tests and three remote SPAN tests; those modules and tests are owned by the main task. The final source checkpoint passes299/299 tests and typechecking (`.cache/final-measured-parity.log`). Six resolver cases include actual weighted recursive UDP distribution and branch failure. The main task separately verifies the browser/build artifact. Run:

```sh
npm run typecheck
npm test
npm run build
```

The repository declares Node >=24.15.0. During core development the system Node22.18 compatible invocation was `node --experimental-strip-types --test --test-concurrency=1 tests/*.test.ts`. Tests require no browser, network service or copied reference runtime. Browser/UI validation is recorded by the main task.

The SLAAC lifetime update rule follows [RFC 4862 section 5.5.3(e)](https://www.rfc-editor.org/rfc/rfc4862#section-5.5.3). The simulator applies the unauthenticated advertisement rule; it does not implement SEND.
